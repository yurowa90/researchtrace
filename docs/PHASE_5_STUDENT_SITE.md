# 사이트 분리 5단계: 학생 전용 탐구 기록

학생·교사·관리자는 서로 다른 주소에서 역할에 맞는 화면을 사용합니다. 학생 사이트는 본인의 학생부 분석과 기록을 확인하고 질문·실행·피드백을 이어가는 공간입니다. AI 분석은 기존대로 Work에서 수행하고 확인된 결과를 반영합니다.

## 화면과 사용 순서

| 화면 | 학생이 할 수 있는 일 |
| --- | --- |
| 오늘 할 일 | 작성 중·진행 중·보완 요청 기록, 제출 대기, 최근 교사 피드백, 탐구 요약과 키워드 확인 |
| 내 질문·실행 기록 | 질문·다음 할 일·읽기 성찰·분석 정정 요청 작성, 작성 중 저장, 검색·상태 필터, 다음 질문 연결 |
| 실행 결과 제출 | 저장한 기록에 실행 근거와 달라진 생각 제출, 교사 보완 요청에 다시 제출, 이전 버전 유지 |
| 선생님 피드백 | 학생에게 공개된 피드백과 상태 확인, 해당 기록으로 바로 이동 |
| 나의 연구 기록 | 연구지문·연결망, 교과 성적 꺾은선 그래프, 과목별 성적·실제 이수학점, 창체·세특 활동 모아보기, 역량 점검, LLM 위키 |
| 진학·과목 계획 | 관심 대학·전형·모집단위, 네 단계 목표, 선택 이유, 학교 개설 과목 계획 저장 |
| 학생부 원본 | 본인 원본과 포함 학년 확인·다운로드, 현재 학년 자료 포함 여부 확인 |

‘새 질문’에서 제목과 궁금해진 이유를 적고 저장합니다. 기록의 ‘실행 결과 제출’에서 실제로 한 일과 근거를 적으면 선생님의 확인 목록에 표시됩니다. ‘보완 요청’에는 같은 기록에서 결과를 다시 제출합니다. 교사가 확인하거나 마친 기록은 보존하고 ‘다음 질문 연결’로 후속 탐구를 시작합니다.

작성 중으로 저장한 내용도 담당 교사와 관리자가 확인할 수 있음을 작성 화면에서 안내합니다. 저장 오류나 버전 충돌이 나면 입력을 유지합니다. 질문·제출 창에서 저장하지 않고 닫으려 할 때 안내하며, 새로고침 이탈도 경고합니다. 질문 초안을 브라우저 영구 저장소에 보관하지 않습니다. 날짜 집계는 한국 날짜를 사용합니다. 기한이 지난 작성 중 초안은 지연으로 계산하지 않습니다.

평가 자료 지정·판본 승인은 교사·관리자의 기존 권한을 따릅니다. 학생은 성적·분석 결과·교사 관찰을 직접 고치지 않고 정정 요청을 남깁니다. 학생의 계획 과목은 실제 수강·이수학점과 구분됩니다. 성적 체계나 근거가 불명확하면 기존 분석 화면의 ‘확인 필요’ 상태를 유지합니다.

## 본인 자료와 공개 범위

- `/api/student`는 저장된 학교 역할·상태·사이트 연결을 재확인합니다. 학생 본인의 학교 계정 ID에 연결된 학생 한 명만 조회합니다. 다른 학생 ID를 URL이나 요청에 넣으면 거부합니다. 중복 연결도 중단합니다.
- 학생 응답에는 다른 학생 자료, 학교 계정 목록, 학급 초대 코드, 교직원 전용 지도 기록, 공용 자료 원본 목록을 담지 않습니다. 적용된 평가 기준만 필요한 범위에서 제공하고 관련 파일은 기존 서버 권한 검사를 거칩니다.
- 교직원 전용으로 바뀐 최신 기록은 과거 공개 버전도 열 수 없습니다. 현재 공개된 기록의 이력에서도 비공개 버전은 제외합니다.
- 관리자에게는 최소 학생 목록을 제공한 후 선택한 한 학생의 공개 화면을 보여 줍니다. 이 화면은 읽기 전용이며 비공개 지도 메모도 제외합니다. 학생 역할로 위장하거나 학생 대신 제출하지 않습니다. 관리 작업은 관리자·교사 사이트에서 수행합니다.
- 학생 쓰기는 질문·할 일·성찰·정정 요청·본인 계획 및 실행 결과 제출만 허용합니다. 교사 피드백·확인 상태 위조, 교직원 전용 항목 생성, 다른 학생 기록 연결, 관리자 작업은 차단합니다.
- 원본·프로필 버전·학생 ID·Google 표 구조를 변경하지 않습니다. 졸업·보관 데이터와 변경 이력을 유지합니다.

## 첫 로그인과 등록 명단 연결

1. 관리자가 실제 학생을 학번·이름·이메일과 함께 등록합니다. 기존 엑셀 일괄 등록을 사용할 수 있습니다.
2. Google 공통 저장소 연결과 사이트 접근 공유를 완료한 뒤 학생이 학생 사이트에 로그인합니다. 처음 접속한 사이트의 로그인은 자동으로 학교 계정에 합쳐지지 않으며 승인 대기로 등록됩니다.
3. 관리자 사이트의 ‘공통 계정 연결’에서 해당 학생 요청을 엽니다. 이메일이 일치하는 등록 학생 중 학번·이름·본인을 확인해 대상을 선택합니다.
4. 확인 근거와 본인 확인 표시를 남기고 ‘학생 명단·로그인 연결’을 누릅니다. 신규 학교 학생 계정을 만들거나 기존 대기 학생 계정을 승인하고 명단과 로그인 연결을 한 번에 저장합니다.
5. 학생이 ‘연결·승인 상태 다시 확인’을 누르면 본인 자료가 나타납니다.

같은 이메일의 교직원 계정, 정지 계정, 다른 학생에 연결된 계정, 다른 계정에 연결된 명단, 예시 명단은 신규 학생 연결로 덮어쓰지 않습니다. 이메일 일치만으로 자동 승인하지 않습니다. 계정·학생 연결·승인·감사 이력은 Google 전체 리비전 검사를 거치는 동일 커밋에 저장합니다. 기존 승인된 학교 계정은 기존 수동 사이트 연결 절차도 사용할 수 있습니다.

## 소스와 설정

GitHub `main`, `sites/teacher`, `sites/student`는 공통 소스를 사용하고 각자의 `.openai/hosting.json` 사이트 ID만 다르게 유지합니다. 변경 소스는 각각의 Sites 저장소에도 보냅니다.

학생 사이트는 `TRACE_PORTAL_MODE=student`, `TRACE_HOME_SITE_ID`는 기존 관리자 기준 사이트 ID, `TRACE_ADMIN_PORTAL_URL`은 관리자 주소를 사용합니다. 이전이 완료된 공통 연결 JSON은 `TRACE_SHARED_GOOGLE_CONNECTION` 비밀 환경 변수에 설정합니다. 관리자 사이트에는 `TRACE_STUDENT_PORTAL_URL`을 설정해 학생 화면 링크를 제공합니다. 비밀키는 Git에 저장하지 않습니다.

공통 저장소가 연결되지 않은 별도 학생 사이트는 ‘학교 자료 연결 준비 중’을 표시하고 읽기·쓰기를 중단합니다. 별도 D1에 새 학교 자료를 자동 저장하지 않습니다. 연결 이후 승인 대기·명단 미연결·역할 불일치·일시 오류를 각각 안내합니다.

## 검증과 실제 운영 전 남은 일

자동 검증 83개 통과: 기존 관리자·교사·파일·Google·교과 검증과 함께 학생 역할·본인 범위·비공개 이력·중복 연결·위조 작업 차단, 작성→제출→보완→확인 이력, 신규 학생 명단 연결, Google 리비전 경계 저장을 검증했습니다. 브라우저에서는 가상 학생의 작성 중 저장·결과 제출·피드백 보완·과목 계획 저장·연구 조회를 확인합니다. 실제 학생 개인정보를 테스트에 사용하지 않습니다.

WebMCP 화면 이동 도구를 등록합니다. 현재 검증 브라우저는 `modelContext`를 제공하지 않아 실제 도구 호출 검증은 불가능했습니다. 화면 버튼 동작은 별도로 검증하며 WebMCP는 자료를 저장·제출하지 않습니다.

운영 Google 연결·소유자 Apps Script 승인·실제 자료 이전은 아직 완료되지 않았습니다. 사이트 공개 범위는 소유자 전용으로 유지합니다. 실제 사용을 시작하려면 기존 Google 설치 안내에 따라 공통 저장소 연결·이전, 두 별도 사이트의 비밀값 설정 및 재배포, Sites 공유 대상 지정, 학교 계정 연결과 학급 배정을 완료해야 합니다. 개발 환경 검증은 이러한 운영 절차를 대신하지 않습니다.
