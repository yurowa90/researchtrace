작업일: 2026-09-17. 범위는 기존 사이트의 분리 준비다. 학생·교사·관리자 사이트의 실제 분리와 공통 인증은 후속 단계에서 수행한다.

## 운영 확인이 남은 항목

코드 구현과 실제 운영 자료 백업은 별개다. 작업 연결에서 확인한 운영 저장소는 기존 D1/R2이며 Google 전환은 완료되지 않았다. 운영 데이터 열람 도구는 긴 분석 JSON을 일부 생략하고 원본 파일 전체를 제공하지 않아 완전한 백업 수단으로 사용할 수 없다. 작업 연결에는 앱 관리자 로그인 세션이 없어 관리자 전용 백업을 대신 실행하지 못했다.

따라서 실제 운영 백업을 만들었다고 기록하지 않는다. 관리자가 배포된 HTTPS 사이트에 로그인해 아래 절차를 마쳐야 운영 준비 확인까지 완료된다.

1. 학교 설정 → 자료 연결 점검하기. 오류와 확인 사항을 살핀다. 미연결 학생 계정은 자료 손상이 아니며 별도 확인 사항으로 표시한다.
2. 점검 결과 저장. 이 JSON에는 개수와 점검 항목이 있으며 학생부 원문·이름·이메일은 포함하지 않는다. 이 파일은 백업이 아니다.
3. 전체 백업 받기. 검증을 통과한 ZIP을 학교에서 승인한 비공개 위치에 보관한다.
4. 백업 파일 검증으로 받은 ZIP을 다시 선택하고 결과를 확인한다. 파일은 브라우저 안에서 검사한다.

백업은 최대 250MB다. 브라우저 검증은 Web Crypto가 제공되는 HTTPS 연결에서 동작한다. 백업은 암호화된 문서가 아니므로 공개 저장소에 올리지 않는다. 원본은 등록된 세 종류의 파일 목록을 기준으로 포함하며, 목록에 없는 저장소 내부 파일까지 탐색하는 기능은 아니다. 연결 비밀키·개인 설치 코드는 제외한다. 자동 복원과 복구 훈련은 아직 구현하지 않았다. 해시는 백업 내용의 일치 여부를 검사하며 외부 서명·공증을 의미하지 않는다.

## 데이터 계약 1.0

Work JSON의 1.0/1.1/1.2와 별개인 공통 데이터 계약이다. 이번 단계는 기존 표·ID를 변경하거나 운영 자료를 이동하지 않는다.

| 개념 | 기준 |
| --- | --- |
| 학생의 지속 식별자 | `students.id`. 이름·이메일·학번을 영구 식별자로 사용하지 않는다. |
| 로그인 계정 | `users.id`가 내부 계정, `students.userId`가 학생과의 연결이다. 학생 계정 한 개에 여러 학생을 연결하지 않는다. |
| 학번 | 문자열로 앞자리 0을 보존한다. 현재 `classId + studentNumber`가 고유하다. |
| 현재 소속·담당자 | `students.classId → classes.id`, `classes.teacherId → users.id`. 읽기/쓰기 권한은 현재 배정으로 확인한다. |
| 학급 이동 이력 | 기존 `guidanceEntries`의 `enrollment` 수정 이력에 이전·새 학급 및 학번, 실행자, 시각을 보존한다. 이동 후에도 학생·원본·분석 ID는 바뀌지 않는다. |
| 담임의 과거 배정 | 현재 `teacherId`만으로 과거 담당자를 추정하지 않는다. 담당자 변경 이력은 후속 구현 사항이다. |
| 기록 시점 | `grade`/`gradeLevel`은 학년, `schoolYear`는 기록 학년도, 원본 `coverageJson`은 포함 학년·학년도, 분석 `sourceYears`는 분석한 학년도다. |
| 대입 기준 시점 | `admissionsYear`는 대입 학년도다. 학생부의 학년도와 자동으로 동일시하지 않는다. |
| 분석 누적 | `profileSnapshots.id`와 학생별 버전명을 보존한다. 각 하위 항목의 `snapshotId`·`studentId`가 같은 학생을 가리켜야 한다. 활성 버전은 학생당 하나다. |
| 원본 파일 | 데이터에 등록된 `objectKey`와 원본 ID를 유지한다. ZIP의 원본 파일명과 원래 키의 대응은 `manifest.json`에 보존한다. |
| 공용 기준 | 원문 ID·해시·판본·승인 상태·적용 학년도를 함께 보존한다. 학생에게 적용한 분석 출처와 구분한다. |

세 사이트는 같은 DB를 사용하므로 각 사이트에서 학생·계정 ID를 새로 발급해 이중 등록하지 않는다. Sites의 `authUserId`는 사이트마다 달라질 수 있어 그대로 공통 계정 ID로 간주할 수 없다. 2단계에서 확인된 `(siteId, externalSubject) → users.id` 연결과 중앙 권한 검증을 구현한다. 이메일 일치만으로 기존 계정을 병합하지 않는다.

Google Sheets의 `revision`과 충돌 검사를 유지한다. 학생·교사에게 전체 시트나 드라이브 폴더를 직접 공개하지 않고 서버에서 허용된 자료를 골라 반환하는 구조를 유지한다.

## 역할 기준

| 기능 | 학생 | 담임 | 관리자 |
| --- | --- | --- | --- |
| 원본·성적·활동·프로필 읽기 | 본인 | 현재 담당 학급 | 학교 전체 |
| 원본 등록·Work 결과 반영·버전 전환 | 불가 | 담당 학급 | 전체 |
| 질문·성찰·계획 | 본인에게 허용된 기록 | 담당 학급 | 전체 |
| 교사 관찰·확인·피드백 | 공개된 결과 열람 | 담당 학급 | 전체 |
| 학생 등록·계정 연결·졸업 처리 | 불가 | 담당 학급 | 전체 |
| 학급 생성 | 불가 | 본인 담당 학급 | 전체 |
| 담임 지정·교사 승인·학급 이동 | 불가 | 불가 | 전체 |
| 공용 평가 자료 | 적용된 점검 결과 | 읽기·Work 자료 선택 | 등록·판본 승인·선택 |
| 전체 자료 점검·전체 백업 | 불가 | 불가 | 가능 |
| 구글 연결 변경·이전 | 불가 | 불가 | 저장소 소유자이기도 한 관리자 |

승인 대기·정지 계정은 접근하지 못한다. 화면 메뉴 숨김과 별도로 서버에서 검사한다. Google 작업은 저장된 현재 역할을 다시 읽으므로 요청에서 역할을 바꿔 보내도 관리자가 되지 않는다. 사이트 공유 허용과 앱 안의 역할 승인은 별개이며 이번 작업은 공유 대상을 변경하지 않는다.

## 검증 범위

- 자동 시험: 전체 백업 왕복, 긴 JSON, 원본 누락·크기 불일치·중간 변경·ZIP 손상, 연결 비밀키 제외, DB 일괄 스냅샷, 자료 관계·개인정보 미노출, 역할 범위·계정 정지·역할 위조, 학급 이동 시 ID·이력 보존.
- 기존 회귀 시험: 대량 학생 등록·충돌·원자성, 현재 학년 기록, 분석 버전, 지도 이력, 평가 판본, 성적 추이·활동 필터.
- 로컬 화면: 예시 학생 3명·분석 2개 버전의 점검 결과 오류 0건, 권한표 표시 확인. 이는 운영 학생 자료 점검 결과가 아니다.
- HTTP 미리보기에서는 브라우저 해시 API를 쓸 수 없어 백업 검증 시 HTTPS 안내가 표시된다. 백업 생성·검증 로직은 자동 시험으로 확인했다. 운영 HTTPS에서 관리자 다운로드 성공은 아직 확인하지 않았다.
- DB 마이그레이션 추가 없음. 실제 학생 원문·명단·백업·연결 키를 GitHub에 저장하지 않음.

2단계를 시작하기 전에는 운영 관리자 백업 생성·보관 결과를 확인하고, 학교의 Google 연결과 사이트 간 로그인 방법을 구체화한다.
