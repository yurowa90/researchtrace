# 사이트 분리 6단계: 학교 관리자 확장

## 화면과 사용 순서

| 메뉴 | 추가 기능 | 집계·저장 기준 |
| --- | --- | --- |
| 학교 연구 현황 | 키워드별 학생 수, 기록 학년도별 원본·활동·교과 보유 현황, 학급별 자료 준비 | 예시 학생 제외, 활성 분석 기준, 같은 학생·키워드와 같은 학생·학년도 중복 제거 |
| 누적 연구 보관함 | 이름·학번·연구 내용 검색, 재학·졸업·보관 상태와 졸업 연도 필터, 학생별 분석 버전 목록 | 검색은 모든 버전의 요약과 활성 키워드에 적용. 과거 키워드 전체에 대한 전문 검색은 제공하지 않음 |
| 보관 분석 상세 | 이전 버전의 연구지문·활동 목차·교과·학점·위키 열람, 원본 JSON 다운로드 | 활성 버전을 바꾸지 않음. 이전 형식이 현재 스키마와 맞지 않아도 요약과 보존 JSON 다운로드 가능 |
| 진급·졸업 일괄 관리 | 최대 100명 진급·학급 이동·졸업·재학 상태 복원, 연속 학번 채우기 | 대상 선택 → 새 학번·사유 입력 → 서버 미리보기 → 최종 확인 → 일괄 저장 |
| 학급·담임 배정 | 담당 교사 변경 전후·영향 확인, 사유 필수 | 승인된 교사·관리자에게만 배정 |
| 학적·담임 변경 이력 | 처리자·시각·사유·변경 전후, 학생별/종류별 검색, 50건씩 더 보기 | 새 관리자 변경 기능에서 생성한 이력. 기존 변경을 소급 생성하지 않음 |

진급은 기존 2학년에서 다음 학년도 3학년 학급으로 처리합니다. 같은 학년의 반 변경은 ‘학급 이동’을 사용합니다. 3학년 졸업 연도는 현재 학급 학년도의 다음 해입니다. 재학 복원은 잘못된 졸업·보관 처리를 기존 학급의 재학 상태로 정정하는 기능입니다.

새 학급은 먼저 ‘학급·담임 배정’에서 만듭니다. 대상 명단의 현재 학번을 기본값으로 사용하고, 연속 학번 채우기는 앞자리 0을 유지합니다. 겹치는 새 학번은 서버에서 거부합니다. 졸업은 자료 삭제나 로그인 계정 정지가 아니며, 기존의 본인/현재 담임/관리자 접근 규칙이 유지됩니다.

## 저장과 권한

- 학생 ID, 계정 연결, 원본 파일, 활동, 연구 흐름, 분석 버전을 보존합니다. 이동 후 새 담임과 학생에게 이전 학급 활동의 과목명도 필요한 범위로 전달합니다.
- 관리자 요청은 저장된 계정 역할·승인 상태·사이트 로그인 연결을 재확인합니다. 교사·학생은 새 학교 통계 API, 운영 이력, 관리자 보관 분석 API를 사용할 수 없습니다. 교사·학생 DTO에는 운영 이력이 포함되지 않습니다.
- 미리보기 해시는 대상 학적, 학급, 담당자와 요청 내용을 포함합니다. 저장 시 재계산하여 오래된 미리보기를 거부합니다. 같은 작업 ID의 재처리도 거부합니다.
- D1은 학생별 조건 확인과 감사 이력 삽입, 학적 갱신을 한 트랜잭션으로 실행합니다. 저장 직전 권한·학적·학급 변경이나 학번 충돌 발생 시 전부 롤백합니다.
- Google은 전체 리비전 검사를 통과한 동일 커밋으로 학적과 이력을 함께 저장합니다. Apps Script는 기존 운영 이력의 수정·삭제를 거부합니다.
- `schoolOperations` 테이블은 학교 점검·스냅샷·전체 백업에 포함합니다. D1 마이그레이션 `0007_eager_marvel_zombies.sql`은 새 테이블·인덱스와 변경/삭제 금지 트리거를 추가합니다. 이전 마이그레이션은 수정하지 않았습니다.
- 기존 Google 저장소의 읽기는 새 테이블이 없어도 지원합니다. 새 학적 변경을 저장하기 전에 최신 설치 코드로 `setupTrace`를 실행하고 웹 앱을 갱신해야 합니다. 새 빈 시트를 추가해도 기존 자료 검증 해시는 유지됩니다.

## 집계 해석

키워드는 분석된 학생 수를 보여주며 키워드 가중치를 학생 간 역량 점수로 합산하지 않습니다. 연도 그래프의 0은 등록된 자료가 없다는 뜻입니다. 성적이나 활동 수준이 낮다는 뜻으로 해석하지 않습니다. 선택된 학생의 현재·최종 학급 학년도와 학생부에 기록된 학년도를 구분하여 표시합니다.

## 검증

자동 검증 91개와 TypeScript 검사를 통과했습니다. 브라우저에서는 두 명 진급·연속 학번 채우기·확인 후 저장·학생별 변경 이력, 키워드 검색 연결과 이전 분석 상세 열람을 검증했습니다. 포함 학년도가 숫자 배열로 저장된 기존 분석에서 연도 표시가 빠지던 문제도 수정했습니다.

실제 SQL 마이그레이션을 적용한 SQLite/D1 어댑터와 Google Apps Script 모의 환경을 사용합니다. 진급 후 원본·버전·계정 보존, 이전 과목 표시, 담임 접근 범위 변경, 졸업·복원, 중복 학번·잘못된 학년 거부, 저장 직전 변경 시 전체 롤백, 이전 분석 다운로드와 권한 거부, Google 새 시트 호환·이력 변경 금지, 통계 중복 제거를 확인합니다. 브라우저 검증에는 개발 환경의 가상 학생만 사용합니다.

## 운영 상태와 다음 단계

학교의 실제 Google 공통 저장소 연결·소유자 Apps Script 승인·자료 이전은 아직 완료되지 않았습니다. 학생·교사 사이트의 공통 비밀값 설정, 실제 학교 사용자 공유와 계정 연결도 운영 환경에서 확인해야 합니다. 소유자 전용 공개 범위는 유지합니다. 7단계에서 실제 설정을 바탕으로 세 사이트 동시 접근, 자료 반영과 백업을 통합 검증합니다. 자동 복원·삭제·보존 기간 만료 처리는 이번 단계에 포함하지 않습니다.
