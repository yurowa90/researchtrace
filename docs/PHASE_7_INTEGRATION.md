# 사이트 분리 7단계: 통합 점검과 저장소 전환

## 구현 범위

관리자 사이트의 `저장소·백업 → 세 사이트 연결 점검`에서 현재 저장 위치, 서명된 Google 응답, 모든 시트·열, 자료 연결, 학생 계정과 담임 배정을 확인합니다. 결과를 JSON으로 내려받을 수 있습니다. 학생 이름·이메일·원문·연결 키는 결과에 포함하지 않습니다.

`확인됨`은 해당 자동 검사에만 적용됩니다. 실제 학생·교사 로그인, 추가 사이트의 현재 서버 설정과 공유 대상, 내려받은 백업의 보관 위치는 `직접 확인`으로 구분합니다. 승인 이력 수를 현재 접속 성공으로 표시하지 않습니다. 점검 API는 승인된 관리자만 사용합니다.

## 전환 순서

1. 관리자 소유자 계정으로 개인 설치 코드를 받습니다.
2. 기존 Google 데이터 시트의 Apps Script에 설치하고 `setupTrace`를 실행합니다. 최초 실행 권한은 소유자 계정에서 승인합니다. 웹 앱을 배포하거나 기존 배포를 새 버전으로 갱신합니다.
3. 사이트에 웹 앱 URL을 입력하고 `연결 확인`을 누릅니다. 기준 사이트·소유자·폴더·시트와 27개 데이터 표의 열 순서를 모두 검사합니다. `schoolOperations`도 포함합니다.
4. `전환 전 전체 백업 받기`를 눌러 원본 포함 ZIP을 내려받습니다. 브라우저가 ZIP 완성 여부, 데이터·원본 해시와 개수를 검사한 뒤 전환 버튼을 활성화합니다. 내려받은 파일을 학교의 비공개 위치에 보관합니다.
5. 30분 안에 `자료 복사 후 구글 저장소 사용`을 누릅니다. 서버는 서명된 백업 확인값, 학교·소유자·연결 대상·자료 내용 일치를 검사합니다. 백업 이후 자료가 바뀌면 다시 백업해야 합니다.
6. 이전을 시작하면 DB 트리거로 기존 자료 수정을 멈추고, 같은 시점의 자료를 다시 검사합니다. 백업 검사와 수정 중단 사이에 자료가 바뀌면 이전을 취소하고 기존 저장소 수정을 재개합니다.
7. 원본별 크기·SHA-256과 표 데이터를 복사합니다. Google에서 다시 읽은 자료와 모든 행·열이 일치하면 저장 위치를 전환합니다. 행 순서만 달라진 경우는 같은 자료로 판단하며 행 추가·삭제·중복·내용 변경은 감지합니다.
8. 소유자용 공통 저장소 설정을 학생·교사 사이트의 비밀 서버 설정에 반영하고 각 사이트를 다시 배포합니다. 실제 사용자에게 사이트 접근을 부여한 뒤 학교 계정 연결 요청을 본인 확인 후 승인합니다.
9. 실제 학생·교사 계정으로 본인/담당 학급 자료와 원본 열람, 질문 제출과 공개 피드백을 확인합니다. 비공개 교사 관찰과 다른 학급 자료는 보이지 않아야 합니다. 관리자 연결 점검과 Google 저장소에서의 전체 백업도 다시 실행합니다.

대상 Google 시트가 비어 있지 않으면 새 이전을 차단합니다. 다른 자료를 덮어쓰지 않습니다. 중단 후에는 복사된 Google 사본을 삭제하지 않으며, 이어서 복사할 때에는 원본 키와 내용을 확인해 재사용합니다. 기존 D1/R2 자료는 전환 후에도 보존되고 수정이 차단됩니다. 자동 복원은 제공하지 않습니다.

## 검증한 항목

가상 학교 자료를 사용하는 자동 검증 총 98개와 TypeScript 검사를 통과했습니다. 새 통합 검증은 실제 라우트, SQL 마이그레이션과 동결 트리거, HMAC 요청, 저장소의 Apps Script 원문을 함께 실행합니다. Google API와 로그인은 테스트 경계에서 모의합니다.

- 백업 생성·브라우저 검증 → 전환 시작 → 수정 동결 → 원본 복사 → 시트 커밋·재조회 검증 → Google 저장소 백업.
- 백업 후 자료 변경, 만료·변조된 확인값, 다른 학교·소유자·연결 주소, 빈 상태가 아닌 대상 시트 차단.
- 이전 직전 자료 변경 시 안전한 취소와 기존 저장소의 쓰기 재개, 중단된 전환 이어서 실행.
- 이전 버전 Google 코드, 학적 이력 시트 누락, 열 순서 불일치 차단.
- 관리자·교사·학생의 사이트별 로그인 승인, 학생 본인/담임 학급 범위, 비공개 관찰, 진급 후 담임 범위 변경, 로그인 연결 해제 후 접근 차단.
- 비로그인·교사·교차 출처 요청의 관리자 점검·백업·전환 거부, 점검 결과에서 개인정보·비밀키 제외.

브라우저에서는 개발 환경의 연결 점검 버튼과 미연결/확인됨/직접 확인 표시를 확인했습니다. 실제 Google 계정의 OAuth 승인과 실제 학교 사용자 로그인 검증을 대체하지 않습니다.

## 현재 운영 상태와 남은 작업

2026-09-18 작업 중 운영 설정과 연결된 Drive를 읽기 전용으로 확인했습니다. 기존 TRACE 폴더와 하위 4개 폴더, 데이터 시트는 있으나 관리자 사이트의 저장소 연결 행은 없었습니다. 교사·학생 사이트에는 공통 저장소 비밀 설정이 없으며, 세 사이트 모두 소유자만 접근하도록 설정되어 있었습니다. Google 데이터 시트에는 지도·공통 로그인·학적 이력용 새 표가 아직 없었습니다.

따라서 이번 단계는 통합 코드·모의 검증·연결 안내까지 구현한 상태입니다. 실제 Google 운영 전환은 아직 완료되지 않았습니다. 소유자 Apps Script 실행 승인과 웹 앱 URL 연결, 백업·자료 이전, 두 사이트의 공통 비밀 설정, 실제 학교 사용자 공유·계정 승인·로그인 검증이 남습니다. 대화의 Drive 연결 권한은 웹사이트에 자동 전달되지 않습니다.

현재 백업/전환 경로는 전체 데이터와 원본 합계 250MB 한도입니다. 예약 백업·자동 복원·대규모 부하 시험은 포함하지 않습니다. 실제 학생 자료를 가상 검증에 사용하거나 공유 범위를 변경하지 않았습니다.
