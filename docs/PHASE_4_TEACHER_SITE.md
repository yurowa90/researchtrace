# 사이트 분리 4단계: 교사 지도실

관리자 사이트와 별도 주소의 교사 사이트를 구성합니다. 학교 자료와 공통 계정 모델은 기존 구조를 그대로 사용하며 AI 분석은 Work에서 수행합니다.

## 화면과 동선

| 화면 | 제공 기능 |
| --- | --- |
| 오늘의 학급 지도 | 담당 재학생, 제출 확인 대기, 이전 학년 원본 부족, 분석 준비·갱신 필요 현황 |
| 담당 학생 | 담당 학급 선택, 학번·이름·이메일·연구 키워드 검색, 재학/졸업/보관 필터, 30명 단위 목록, 엑셀 양식·일괄 등록 |
| 확인할 상담 | 제출 확인 대기·정정 요청·확인일 경과 필터, 학생과 해당 기록으로 직접 이동, 평가 기준 재점검 |
| 상담·관찰·피드백 | 질문 성장, 관찰 사실과 해석, 교사 확인·보완 요청, 공개 범위, 수정 이력 |
| 학생부 원본 | 기존 원본 등록·열람·자료 묶음, 현재 학년을 포함한 복수 학년 지정 |
| 학생 연구 기록 | 연구지문, 교과·성적 그래프, 활동 모아보기, 역량 점검, LLM 위키, 진학·과목 계획 |
| Work 결과 | 학생별 분석 요청문·자료 묶음, 분석 JSON 검토·반영, 활성 버전 선택 |
| 공용 평가 자료실 | 관리자가 등록한 자료의 열람·다운로드·Work 사용 자료 선택 |

홈과 상담 대기는 재학생 기준입니다. 예시는 기본적으로 제외하고 교사가 명시적으로 표시할 수 있습니다. 상담 대기는 각 기록의 최신 버전만 사용합니다. 임시저장·확인 완료·종료된 기록을 미처리로 집계하지 않습니다. 확인일은 한국 날짜를 기준으로 비교하며 오늘 예정은 기한 경과가 아닙니다. 제출 대기와 정정 요청은 한 기록에 함께 표시될 수 있지만 전체 건수에서는 중복하지 않습니다.

분석 준비·갱신은 활성 분석이 없거나 미반영 원본이 있는 학생을 뜻합니다. 학생 역량 점수나 입시 결과 예측이 아닙니다. 이전 학년 필수 자료와 현재 학년 추가 자료를 구분합니다.

## 권한과 저장

- 교사 `/api/teacher`는 저장된 역할·계정 상태·사이트 연결을 재확인합니다. 교사는 현재 담당 학급만, 관리자는 전체 학급을 열람합니다. 화면에서 권한을 바꾸지 않습니다.
- 대기 계정에는 승인 대기 상태만 제공하고 학급·학생 자료를 반환하지 않습니다. 정지·연결 해제·학생 역할은 교사 자료에 접근할 수 없습니다.
- 교사 화면의 일반 변경 요청은 학생 등록·일괄 등록·Work 결과 반영·활성 버전·개인 자료 선택만 허용합니다. 각 대상 학생·학급 접근 검사는 공통 서버에서 다시 수행합니다. 원본·지도 API도 기존 공통 권한을 적용합니다.
- 학급 생성·배정, 학교 계정 승인, 사이트 간 로그인 연결 승인, 학생 학급 이동·졸업 처리, 자료 판본 승인, 저장소 이전·전체 백업은 관리자 사이트에서 처리합니다. 교사 사이트에는 해당 운영 메뉴를 배치하지 않습니다.
- 별도 교사 사이트는 `TRACE_SHARED_GOOGLE_CONNECTION`이 없으면 연결 준비 상태를 표시하고 조회·저장을 중단합니다. 새 로컬 D1에 학교 데이터를 분산 저장하지 않습니다.
- 기존 학생/자료 ID, 이력, 원본 파일, Google 표 구조는 변경하지 않습니다. Google 이전 전 자료는 관리자 사이트의 기존 D1/R2에 그대로 남습니다.
- 인증이 해제되면 화면 자료를 지우고 접근 안내를 표시합니다. 일시적인 갱신 오류는 기존 입력 화면을 유지하되 다시 확인하기 전 추가 저장을 막습니다.

## 배포와 공통 소스

관리자 주소: https://class-research-profile.yurosung.chatgpt.site

교사 주소: https://researchtrace-teacher.yurosung.chatgpt.site

GitHub `main`은 관리자 사이트의 기존 `.openai/hosting.json`을 유지하며 두 사이트에서 사용할 공통 소스를 포함합니다. `sites/teacher`는 동일 소스에 교사 사이트의 별도 `.openai/hosting.json`을 적용한 배포 브랜치입니다. 각각의 네이티브 Sites 소스 저장소에도 정확한 배포 소스를 보냅니다. 관리자 저장소의 manifest를 교사 ID로 덮어쓰지 않습니다.

서버 환경 설정:

| 설정 | 관리자 사이트 | 교사 사이트 |
| --- | --- | --- |
| `TRACE_PORTAL_MODE` | `admin` | `teacher` |
| `TRACE_HOME_SITE_ID` | 기존 기준 사이트 ID | 같은 기준 사이트 ID |
| `TRACE_TEACHER_PORTAL_URL` | 교사 사이트 주소 | 필요 없음 |
| `TRACE_ADMIN_PORTAL_URL` | 필요 없음 | 관리자 사이트 주소 |
| `TRACE_SHARED_GOOGLE_CONNECTION` | 기존 연결 설정 유지 | 이전 완료 후 생성한 공통 연결 JSON을 비밀값으로 설정 |

비밀키와 Drive 파일 ID, 실제 학생 데이터, 개발 `.dev.vars`는 Git에 저장하지 않습니다.

## 실제 사용을 시작할 때 필요한 순서

1. 소유자가 관리자 사이트의 저장소·백업에서 원본 포함 백업을 생성·검증합니다.
2. Google 설정 안내에 따라 소유자 계정에서 Apps Script 설치·실행 권한 승인·웹 앱 배포를 완료하고 기존 자료를 이전합니다.
3. 관리자 화면에서 생성한 공통 연결 설정을 교사 사이트의 비밀 환경 변수로 적용하고 재배포합니다. 키를 공개 저장소나 채팅 본문에 붙여넣지 않습니다.
4. 실제 교사가 사이트에 접근할 수 있도록 소유자가 Sites 공유 대상을 지정합니다. 구현 시의 소유자 전용 공개 범위는 자동 확대하지 않습니다.
5. 교사가 로그인하면 생성되는 사이트 계정 연결 요청을 관리자가 본인 확인 후 학교 교사 계정에 연결합니다. 기존 학교 계정이 없다면 소속 확인 표시와 확인 근거를 남기고 ‘새 교사 계정 생성 후 연결’을 사용합니다. 같은 이메일의 기존 계정은 자동 합치지 않으며 기존 계정의 승인 상태를 먼저 확인합니다. 담당 학급을 배정하고 새로고침합니다.

구현 시 운영 공통 Google 연결은 완료되지 않았습니다. 별도 교사 사이트는 이 상태를 명시적으로 안내합니다. 개발 환경의 가상 데이터 검증은 운영 Google 권한 승인·실제 자료 이전·실제 교사 공유 및 계정 연결을 대신하지 않습니다.

## 검증

교사 전용 API의 비로그인·학생·승인 대기·정지·해제된 연결, 담당 반 범위, 다른 반 등록 차단, 관리자 작업 거부, 공통 저장소 미연결 시 중단, 상담 최신 버전·한국 날짜·중복 처리 집계를 자동 검증합니다. 기존 권한·원본·Google·성적·지도 회귀 시험을 함께 실행합니다. 브라우저에서는 가상 학생으로 상담 직접 이동, 피드백 저장과 이력 유지, 학생 검색·원본·연구 탭, 연결 준비 화면을 확인합니다.
