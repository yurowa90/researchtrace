# Google Drive · Google Sheets 연결

사이트 관리자의 **학교 설정 → 내 구글 저장소 연결**에서 진행합니다. 이 대화에 연결된 Google 권한이 웹사이트에 자동으로 전달되지는 않습니다.

1. **설치 코드 준비**를 누릅니다. 소유자 전용 코드에는 연결 키가 들어 있으므로 GitHub에 올리지 않습니다.
2. **데이터 시트 열기 → 확장 프로그램 → Apps Script**를 선택합니다.
3. Code.gs를 개인 설치 코드로 바꾸고 저장합니다. 왼쪽 **서비스 + → Google Sheets API → 추가**를 누릅니다. `setupTrace` 함수를 한 번 실행하고 지정한 Google 소유자 계정으로 권한을 승인합니다.
4. **배포 → 새 배포 → 웹 앱**을 선택합니다. 실행 사용자는 **나**, 액세스는 **모든 사용자**로 설정합니다. 이 설정은 서명 요청을 받을 서버 진입점만 열며, Drive 폴더나 시트를 공개 공유하지 않습니다. `doGet`은 데이터를 반환하지 않고, `doPost`는 HMAC 서명과 유효 시간을 검사합니다.
5. `/exec`로 끝나는 배포 URL을 사이트에 입력하고 **연결 확인**을 누릅니다.
6. **전환 전 전체 백업 받기**를 눌러 ZIP 다운로드와 데이터·원본 검증을 마칩니다. 백업을 보관한 뒤 30분 안에 **자료 복사 후 구글 저장소 사용**을 누릅니다. 백업 이후 자료가 달라지면 새 백업을 받습니다. 원본별 크기·SHA-256과 데이터 내용을 확인한 다음 저장 위치가 전환됩니다. 복사 중에는 화면을 닫지 않습니다. 원본 복사 단계에서는 **이어서 복사·검증** 또는 **이전 중단**을 사용할 수 있습니다. 최종 검증·저장 확인 단계에서 응답이 끊기면 **완료 확인 다시 실행**을 누릅니다. 다른 요청이 실행 중이면 완료를 기다리거나 3분 뒤 다시 확인합니다.

기본 Apps Script 프로젝트에서는 서비스를 추가하면 해당 API가 자동 활성화됩니다. 별도의 표준 Google Cloud 프로젝트를 연결한 경우에는 그 프로젝트에서 Google Sheets API도 활성화해야 합니다. [Google 공식 설정 안내](https://developers.google.com/apps-script/guides/services/advanced).

Google Workspace 정책상 익명 웹 앱 배포가 금지된 계정에서는 이 방식이 동작하지 않습니다. 정책을 임의로 바꾸지 말고 학교에서 승인한 별도 OAuth 서버 방식을 사용해야 합니다.

## 보관 위치와 권한

- 학생부와 첨부 파일: 소유자의 `01 학생부 원본` 폴더
- 대학 모집요강·평가 기준: `02 공용 평가 자료` 폴더
- 길이가 긴 분석 원문: `03 분석 결과` 폴더. 일반 필드와 분석 이력은 데이터 시트의 해당 탭에 저장됩니다.
- `04 설정과 백업`: 사용자가 관리할 백업 폴더입니다. 정기 자동 백업은 아직 설정하지 않았습니다.
- 학생은 본인, 교사는 담당 학급, 관리자는 학교 전체와 졸업생을 사이트에서 조회합니다. 데이터 시트 전체를 학생이나 담임에게 공유하면 사이트의 범위 제한이 적용되지 않으므로 소유자만 접근하게 유지합니다.
- 구글 전환 후 새 학생 데이터는 Sheets·Drive에 기록합니다. 기존 D1/R2의 이전 전 사본은 자동 삭제하지 않습니다. 사이트의 연결 주소·비밀키·연결 상태는 서버 설정 DB에 남습니다.
- Sheets 열 이름, 행 ID, `_meta`, `_files`를 직접 수정하지 않습니다. 데이터 변경은 사이트에서 합니다. 무결성 검사와 충돌 검사가 수동 편집·동시 변경으로 인한 덮어쓰기를 차단합니다.

## 운영과 검증 범위

이 구현은 Google Sheets 전체 데이터를 읽어 서버에서 권한을 적용하고 변경한 표를 저장합니다. 누적 데이터와 동시 사용자가 커질수록 읽기 시간과 Google API 한도가 제약이 됩니다. 여러 학교를 수용하는 대규모 운영의 성능 검증은 하지 않았습니다.

Google Apps Script는 실행 시간과 일일 호출 한도가 있으며 Drive 용량도 계정 상품에 따라 달라집니다. 무료·무제한 운영을 보장하지 않습니다. [Apps Script 할당량](https://developers.google.com/apps-script/guides/services/quotas), [Google 웹 앱 실행 권한](https://developers.google.com/apps-script/guides/web).

Google 배포·승인은 계정 소유자가 직접 해야 합니다. 로컬 검증은 역할 제한, 300명 등록, 버전 보존, 요청 서명, 재전송 거부, 데이터 충돌, 파일 검증과 Sheets API 경계 모의 테스트를 포함합니다. 실제 Google 계정에서의 전체 동작은 설치 후 연결 확인·자료 복사 절차가 검증합니다. 보안 감사를 완료했다는 의미는 아닙니다.

## 개발자 설정

서버 환경 변수 `TRACE_GOOGLE_LOCATIONS`에 아래 키를 가진 JSON을 설정합니다. 계정별 값과 연결 비밀키를 저장소에 커밋하지 않습니다.

```json
{
  "ownerEmail": "계정 소유자 이메일",
  "folderId": "상위 폴더 ID",
  "recordsFolderId": "학생부 폴더 ID",
  "referencesFolderId": "공용 자료 폴더 ID",
  "resultsFolderId": "분석 결과 폴더 ID",
  "backupsFolderId": "백업 폴더 ID",
  "spreadsheetId": "데이터 시트 ID"
}
```

`google/Code.gs`의 `__TRACE_CONFIG__`는 사이트가 개인 설치 코드를 만들 때만 치환합니다. 저장소의 템플릿을 그대로 실행하면 설정되지 않습니다. Apps Script 코드가 변경되면 기존 배포의 새 버전을 게시해야 합니다. Sites 서버와 Google 백엔드의 스키마를 함께 유지합니다.

Apps Script의 `DriveApp`은 전체 Drive 접근 OAuth 범위를 요구합니다. 코드에서는 지정한 저장소만 사용하며 임의 파일 ID를 클라이언트에서 받지 않습니다. 더 좁은 OAuth 범위가 필수라면 별도 Google Cloud 앱과 `drive.file` 방식을 구성해야 합니다.

## 지도 기록·공통 계정 기능을 위한 기존 연결 갱신

이미 Google을 연결했다면 학교 설정에서 새 설치 코드를 받습니다. 기존 Apps Script 프로젝트의 코드를 교체하고 `setupTrace`를 다시 실행한 뒤 기존 웹 앱 배포를 새 버전으로 갱신합니다. 기존 주소를 유지하고 사이트에서 연결 확인을 누릅니다. 이 과정은 기존 표의 행을 그대로 두고 누락된 `guidanceEntries`, `schoolIdentities`, `identityEvents`, `schoolOperations` 표를 추가합니다. 기준 학교 사이트 식별자도 저장합니다. 연결 확인·갱신 확인·이전·추가 사이트 설정 발급은 전체 표와 열 순서, 소유자·기준 학교·폴더·시트 일치 및 원본 내용 검증 기능을 검사합니다. 기존 열 이름이나 값을 직접 변경하지 마세요.

갱신 전의 연결에서는 기존 기준 사이트 계정을 사용할 수 있지만 새 지도 기록과 사이트 계정 연결 저장은 코드 갱신 안내로 중단됩니다. 추가 사이트는 기준 학교와 공통 계정 표를 확인하기 전에는 접근하지 못합니다. 누락된 표를 무시하고 저장 완료로 표시하지 않습니다. 업데이트 전후의 기존 데이터 유지와 무결성 해시 호환은 모의 Google API 테스트로 확인합니다.

연결 후 ‘데이터 백업 만들기’는 지정한 비공개 백업 폴더에 표 데이터와 파일 위치 목록을 JSON으로 보존합니다. 연결 비밀키는 포함하지 않습니다. 원본 파일의 독립 사본, 자동 백업 일정, 자동 복원 기능은 포함하지 않습니다.

## 여러 사이트가 같은 저장소를 사용하기

기준 사이트에서 최신 코드 연결과 자료 이전을 완료한 다음 소유자 관리자가 ‘추가 사이트 연결 설정’에서 설정 파일을 받습니다. 이 파일은 비밀키를 포함하므로 서버 설정 담당자만 사용하며 GitHub·학생 화면에 올리지 않습니다. 각 추가 사이트에 `TRACE_HOME_SITE_ID`, 비밀 환경 변수 `TRACE_SHARED_GOOGLE_CONNECTION`, 사이트 용도에 맞는 `TRACE_PORTAL_MODE`를 설정합니다. 자세한 값의 형식과 계정 승인 절차는 [2단계 안내](PHASE_2_SHARED_FOUNDATION.md)에 있습니다.

## 운영 전 최종 점검

학교 설정의 **세 사이트 연결 점검 → 지금 연결 점검**으로 현재 저장 위치와 저장소 응답, 자료 연결, 학생 계정·담임 배정을 확인합니다. ‘확인됨’은 표시된 자동 점검 항목에만 적용합니다. 다른 사이트의 서버 설정이나 공유 범위를 원격으로 확정하지 않습니다.

대상 시트에 이미 다른 자료가 있으면 이전을 시작하지 않습니다. 원본 복사 중 오류는 **이어서 복사·검증**으로 재시도할 수 있습니다. 복사 단계의 이전 중단은 기존 저장소 사용을 재개하며 Google 쪽에 복사된 사본을 삭제하지 않습니다. 최종 검증을 시작하면 이전 중단을 차단합니다. 원격 저장 전 검증 실패는 복사 단계로 돌아가지만, 원격 저장 여부가 불확실하면 기존 기록을 동결하고 **완료 확인 다시 실행**으로 저장 결과를 대조합니다. 최종 검증에서는 파일 목록뿐 아니라 실제 Drive 원본의 존재·보관 폴더·크기·SHA-256을 확인합니다.

원본 포함 ZIP 백업은 최대 250MB이며, 대용량 학교 자료는 이 한도 내에서만 현재 전환 절차를 사용할 수 있습니다. 자동 복원·예약 백업·대규모 동시 접속 시험은 제공하지 않습니다. 상세 절차와 실제 확인 범위는 [7단계 안내](PHASE_7_INTEGRATION.md)에 있습니다.
