## 이번 보완 사항

- 관리자 화면에 담임 승인, 학급 담당자 지정, 학생 계정 연결 기능을 추가했다.
- 관리자 전체 보기에서 학생 추가 시 첫 학급으로 자동 배정되던 문제를 없애고 학급을 반드시 선택하도록 했다.
- 담임에게 학교 전체 승인 대기 계정이 노출되던 문제를 수정했다. 담당 학생 이메일과 일치하는 대기 계정만 반환한다.
- 교사·관리자 계정 이메일을 학생에게 연결해 역할이 강제로 바뀔 수 있던 권한 상승·강등 문제를 차단했다.
- 승인 대기 상태가 아닌 계정, 이메일이 불일치하는 계정, 이미 다른 학생과 연결된 계정, 정지 계정의 연결을 차단했다.
- 학생이 숨은 API를 직접 호출해 활동·분석·탐구 흐름을 수정할 수 있던 경로를 교사·관리자 전용으로 제한했다.
- 프로필 이력 목록과 이전 버전 활성화 기능을 추가했다. 학생은 읽기 전용으로 이력을 본다.
- Work 결과 가져오기 중 오류가 나도 기존 활성 프로필이 유지되도록 새 버전을 비활성 상태로 완성한 뒤 원자적으로 전환한다.
- 포털 응답에서 프로필 원본 JSON 전체를 제외해 불필요한 개인정보·분석 원문 전송을 줄였다.

## 아직 구현하지 않은 작업

1. Work 분석을 사이트에서 직접 실행하거나 Work 결과를 자동 전송하는 연동. 현재는 JSON 파일·붙여넣기 방식이다.
2. 모집요강·평가기준 원문 파일 자체의 업로드, 출처 저장, 적용 기간·버전 관리. 현재는 Work가 만든 구조화 평가 결과만 저장한다.
3. 학급 단위 일괄 학생 등록, 학생부 일괄 업로드, 학년도 승급·반편성 이관.
4. 관리자 감사 로그. 누가 언제 조회·업로드·승인·졸업 처리·버전 전환을 했는지 별도 이력으로 남기지 않는다.
5. 개인정보 보존기간, 졸업 후 열람 정책, 파기·복구 승인 절차의 학교별 설정.
6. 과거 프로필 버전의 전체 연구지문·위키를 활성화하지 않고 나란히 비교하는 화면. 현재는 메타데이터 이력과 활성 버전 전환을 지원한다.
7. 학교 단위 종단 분석. 현재 학교 집계는 학생 수·원본 준비·활성 프로필·키워드 중심이며 연도별 코호트 비교는 없다.
8. 학생·보호자용 PDF 보고서와 인쇄 레이아웃.
