# TRACE 학생 연구 프로파일

2·3학년 학생부와 Work 분석 결과를 누적 관리하는 학교 포털입니다.

현재 주소는 학교 관리자 사이트입니다. 운영 현황·학생 관리·학급 배정·계정 승인·자료실·저장소를 관리하며, 학생별 상세 자료는 ‘학생 자료 열람’에서 확인합니다. 교사 지도실과 학생 전용 사이트는 별도 주소에서 같은 공통 소스를 사용합니다. 실제 공동 사용은 Google 연결·자료 이전과 학교 계정 승인을 마친 뒤 시작합니다.

- 학생 본인 · 담당 학급 담임 · 학교 관리자 권한을 구분합니다.
- 엑셀 양식과 붙여넣기로 학생을 최대 300명까지 일괄 등록합니다.
- 이전 학년과 현재 학년의 실제 기록을 함께 분석하고 버전을 보존합니다.
- 교과 선택, 성적 변화, 과목군별 학점, 연구지문, 온톨로지, LLM 위키를 표시합니다.
- 관리자가 공용 모집요강·평가 기준을 등록하고 교사가 Work에서 재사용합니다.
- 질문·실행 결과·교사 관찰·피드백을 수정 이력과 함께 보존합니다.
- 네 단계 목표와 과목 계획을 실제 이수 내역과 구분하며, 기준 개정 시 재점검을 안내합니다.
- 원본 최대 50개를 대상 학생·포함 학년 확인 후 등록하고 학생별 Work 자료 ZIP을 받습니다.
- 원본 파일은 소유자 Google Drive, 구조화된 기록은 Google Sheets로 연결할 수 있습니다.
- 관리자 학교 설정에서 자료 연결·권한 기준을 점검하고, 원본과 모든 분석 버전을 포함한 전체 백업을 내려받아 검증합니다.
- 새 사이트의 로그인을 기존 학교 계정에 관리자 승인으로 연결하고, 연결 해제와 처리 이력을 관리합니다.

AI 분석은 Work에서 진행합니다. 웹사이트는 외부 LLM을 자동 호출하지 않습니다.

## 개발

Node.js 24와 프로젝트의 pnpm 버전을 사용합니다.

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm build
node --import ./tests/register.mjs --test tests/*.test.mjs
```

React · Vinext · Drizzle 기반이며 Sites에서 호스팅합니다. Sites의 서버 로그인 정보를 사용하므로 다른 호스팅으로 옮길 때에는 인증 연동을 별도로 구현해야 합니다. 로컬 개발용 로그인은 실제 학생 데이터에 사용하지 않습니다.

데이터 구조는 `db/schema.ts`, 사이트 권한과 기존 저장 방식은 `lib/data.ts`, Google 저장 방식은 `lib/google-school.ts`, Google 서버 템플릿은 `google/Code.gs`에 있습니다. 적용된 마이그레이션을 수정하지 말고 새 마이그레이션을 추가합니다.

## 게시

GitHub는 소스 관리에 사용하고 현재 웹사이트는 Sites에 게시합니다. 이 저장소에 커밋하는 것만으로 Sites에 자동 배포되는 CI 연결은 설정하지 않았습니다. Sites의 빌드·버전 저장·게시 절차를 거쳐 변경 사항을 반영합니다.

실제 Google 배포·권한 승인과 데이터 이전은 학교 관리자 설정에서 완료해야 합니다. 검증 범위와 운영 한도는 [연결 안내](docs/GOOGLE_SETUP.md#운영과-검증-범위)에 설명했습니다.
